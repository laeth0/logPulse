### Closed decisions
- OpenWolf supports only Claude and Codex because those are the user's active agents.
- Rollup-first aggregation merges rollup + raw-scan-edge result sets in application code (JS `Map` keyed by `(bucket,group)`), not a SQL `UNION ALL` — the installed TypeORM version's `SelectQueryBuilder` has no union support, and the app-level merge is simple enough to audit directly.
- Attribute-equality predicate emits the numeric/boolean OR-branch SQL text only when the filter value actually parses as that type — always including the branch and gating it with a boolean flag would still error at bind time, since `::numeric`/`::boolean` casts apply to the parameter value itself regardless of surrounding AND/OR logic.
- `queryRunner.query()` has no generic overload (returns `Promise<any>`); use `this.dataSource.query<T>(sql, params, queryRunner)` instead when a typed result is needed within an existing queryRunner's connection/transaction — already the established pattern in `partition.service.ts`.
- Backpressure/admission control was deliberately removed rather than kept disabled-but-present — the user wanted it and its whole surface area (config, domain errors, HTTP exception, env vars, README section, `.rest` examples, spec-kit planning docs) gone, not merely defaulted off. If a similar shed-load feature is ever requested again, treat it as a fresh design, not a resurrection of `specs/003-ingestion-backpressure/` (deleted; recoverable from git history only).
- **Write coalescing (debounced multi-caller batching into fewer `COPY` calls) was deliberately removed** at the user's explicit request — `insertMany()` now opens one transaction per call directly, no queue/timer/batch-merging. `002-performance-optimization`'s planning docs (`specs/002-performance-optimization/`) still describe the old coalescing design and were deliberately left untouched (historical record covering several still-live optimizations — rollups, write-pool sizing, `attributes_text` removal — not solely coalescing). If concurrent-write throughput becomes a bottleneck again, treat re-introducing batching as a fresh design decision, not a revival of the old debounce/queue mechanism.
- **The dedicated read-only PostgreSQL connection pool (named `'read'`) was deliberately removed** at the user's explicit request — one connection pool (sized by `DB_WRITE_POOL_MAX`) now serves ingestion, migrations, retention, and `GET /logs`/`GET /logs/aggregate` reads. This reverses part (not all) of `002-performance-optimization`; if read/write contention resurfaces as a measured bottleneck, treat re-splitting the pool as a fresh decision — don't just resurrect `createReadDatabaseOptions()` from git history without re-justifying it against current measurements.

- **Stack:** Backend: NestJS, TypeORM, PostgreSQL. Frontend: React 19, TypeScript, Vite 8, React Router 7, Material UI 9, Axios, Zod 4.
- **Key tables / modules:** Backend tenancy/log ingestion/query/aggregation/retention; frontend auth (login/register) under `src/features/auth`, the logs workbench (ingest/query/aggregate) under `src/features/logs`, a minimal `src/features/dashboard` page hosting it as tabs, shared Axios transport under `src/shared/api`, session store under `src/store/auth.store.ts`, application routes (with `ProtectedRoute`) under `src/router`.
- **Patterns:** Feature-first frontend modules; per-concern `types/` split once a feature's types file covers more than one concern (domain/hooks/forms/components each own file — see `features/auth/types/` and `features/logs/types/`); Zod validation before requests and after responses; thin async API modules; stateful feature hooks; MUI theme tokens at the application root; direct MUI imports for bundle efficiency; any real chart goes through the `dataviz` skill before the first line of chart code.
- **No local auth override:** the `.env.local` file (previously used to set `AUTH_ENABLED=true` for a local tenant-scoped-auth frontend demo) was removed on 2026-08-17 at the user's request — not needed. `docker compose up` always uses the committed `docker-compose.yml` default `AUTH_ENABLED=false` (required by `docs/Final_Project.md`'s zero-config grading contract). Do not reintroduce a root `.env`/`.env.local` file or a matching `.gitignore` entry for one unless the user explicitly asks again.
- **After any backend source change, always `docker compose up -d --build app`** — `--force-recreate` alone reuses the stale image (bug-035/bug-036 precedent).
